# 1.3.0 stable: punch list

2026-11-23. The plan for the next stable: what to bring from the 2.0 work back to the 1.x line, and
what to do before the cut. Nothing here is cherry-picked yet.

## What was decided

- **1.3.0 is "v1, finished".** It is cut from `dev` (v1.2.2) by cherry-picking. 2.0 stays in the
  pre-release channel until the developer is satisfied with it; #274's 2.0 bar is unchanged.
- **Fixes:** every fix on `v2-redesign` whose bug a v1.2.2 user can hit, if it applies cleanly or
  with a small adaptation in code 1.x still has. A fix that needs v2 machinery rebuilt is left out
  ("Bugs 1.x keeps" below).
- **Features:** only the 1.x-shaped ones that port: they live on a surface 1.x already has. Nothing
  that needs v2's Appearance editor, one-look model, pages, glass, chrome, dock styles, widget
  redesign, wallpapers, page bar or terminal engine.
- **Never ported:** `AppearanceReset` (1.x has none), and anything that migrates the
  v2 look.
- **New work only if cheap:** #165 gets a reproduction on a 1.2.2 emulator build, and a fix if it
  reproduces.
- **Proof:** pong already ran these fixes on the pre line. The 1.3.0 release build gets the two
  emulator checks (fresh install with no network until bootstrap; upgrade over the 1.2.2 APK with a
  customised look); pong is not touched.
- **Ship:** all three editions (`v1.3.0`, `nix-v1.3.0`, `vaj-v1.3.0`), on their own, with no
  paired drop. The pre channel carries on as `2.0.0-pre.8`. Old `v1.3.0-pre.1`–`pre.4` tags (the
  v2 work before its rename) stay; the stable sorts above them.
- **Rule exceptions** are written into `docs/agents/releasing.md` ("A 1.x line beside 2.0").

## How to port

- Base: `origin/dev` at `f3e48dddd`. Work on `rel/1.3.0` (worktree `app/wt-1.3.0`).
- `git cherry-pick -x` oldest first (the tables below are in commit order per area). Doc-only
  clashes (`project-docs/`, `docs/`): keep `dev`'s side and drop the v2 doc hunks.
- "adapt" rows conflict with 1.x code; the note says what differs. If an adaptation grows past a
  few lines or needs a v2 class, move the row to "Bugs 1.x keeps" instead of rebuilding.
- Pairs and order: `ab4e2ab80` ships with `6fa68bcdb`; `9bf6b20f8` follows `cb15f15b7`;
  `087b920d9` ships with `24155ae6a`; `8c0db921e` replaces its duplicate `e9bda687f`; `3235cd097`
  replaces `1aeefa0c9`; `09a998bb1` replaces `9a848a3aa`.
- Script version numbers: `0596ebc4a` and `c37ddd678` bump their setup script's VERSION from the
  1.x value (1.2.2 has 1016 and 21), not the v2 number in the diff.
- Each row's user-facing line is a draft for the 1.3.0 notes, not final copy.
- Check after each area: `./gradlew :app:assembleDebug` and the tests the commits touched; the full
  suite (`scripts/full-suite.sh`) once at the end.
