# Page list (WallPages): design, 2026-10-27

Candidate A of the page architecture review
(https://amal-build.taild9c5dc.ts.net/reports/page-architecture-2026-10-27/), grilled with the
developer on 2026-10-27 under ADR 0015 (proposed). No code yet.

## The module

`wall/WallPages` is an immutable value: the wall's ordered pages and its home.

- `Page`: a stable int id (handed out from a counter, never reused), a **page kind** (Home,
  Terminal, Display), a name, and a Display binding (none, or a Linux app).
- State beside the order: the home target, pages pending removal, and detached pages (kept in the
  store, not on the wall).
- Queries: `pages()`, `home()`, `stops(windowCount)`, `indexOf(stop)`, `neighbours(stop)`, and
  from slice 3 `routeLinuxApp(app)` (bound page, else the first unbound Display page, else a new
  one after the current page).
- Edits return the new value and what changed: `add(kind, after, binding)`, `move`, `remove`
  (marks the page pending; it leaves `stops()` and Edit pages at once), `undo`, `setHome`, `rename`,
  `bind`.
- Rules held by the value: at most one Terminal page; removing the home page makes the first page
  home; removing the last Home page is refused while it is home and alone; a Terminal page with
  windows is removed only after the caller has confirmed closing them.

A **stop** is one place the wall can land: a page, plus a window index on the Terminal page.
`stops(windowCount)` expands the Terminal page into one stop per window of the current session,
or one stop that starts a shell on landing when there is none. It replaces the index arithmetic in
`WallParallax` (:67-78), `PageOverviewPolicy` (positionOfRow :66, wallPosition :184) and `WallRow`
(seamContinues :107, seamStartsShell :117).

## The store

`wall/WallPagesStore` loads and saves the value and notifies owners. Adapters: SharedPreferences
file `wall_pages`, one versioned JSON under `state` (the pattern of `launcher_widget_repository`),
read synchronously at start; and an in-memory adapter for tests. It emits `Removed(p)` only when a
pending removal's undo window closes (or the app stops), and owners delete that page's data then.
`TermuxActivity` builds one store in `onCreate` and passes it to `PaneWallController`, the Edit
pages Host and the widget controller. No singleton.

## Owners keyed by page id

What stands on a page stays with its owner, keyed by page id:

- widgets and icons: `LauncherWidgetRepository`, re-keyed once from index to id (idempotent: only
  pages without an id are re-keyed); `HomePageEdits`' remapping retires;
- Float pins: workspace JSON v5 writes `pageId`; a v4 file maps its index to the Home page at that
  position in the current order on load (else the home page, else the first Home page); the
  autosave is rewritten as v5 at the first stop after upgrade;
- later: look overrides (candidate B), a page's own layout (candidate D).

## Upgrade

Runs in `TermuxApplication`, beside `WallReworkMigration`, gated by its own version key. Reads
Start in (`app_launcher_start_in`), the default Home page (`app_launcher_home_default_page`), Use as
and the widget repository's page count once. Home screen users get [Home 1…n][Terminal]; Terminal
only users get [Terminal], with their old Home pages kept as detached pages, offered back by Edit
pages' Add → Home ("Bring back N Home pages"). Nothing is deleted.

## Slices

1. **Behaviour-neutral.** The module, ids, the migration and the callers switched: wall paging,
   Edit pages' index arithmetic, Start in, Use as, the default Home page. The order stays Home
   pages then Terminal, and the display stays a row window. `home()` may return a transitional
   display-window target until slice 3. `StartInPolicy`, `HomeSettings`' default page and the Use as
   setting retire with no visible change. The existing wall tests (PaneWallLayoutTest,
   PaneWallControllerTest, PageOverviewPolicyTest) prove neutrality; StartInPolicyTest, UseAsTest
   and WallRowTest become WallPages tests.
2. Free order and Set as home for any page in Edit pages.
3. Display pages: the display leaves the row; the transitional target becomes a Display page set
   as home.

Candidate B (the Look of a page) starts after slice 1.
