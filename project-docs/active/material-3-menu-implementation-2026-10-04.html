Material 3 menu rework

Implementation scope approved on 2026-10-04: rework the app’s menu pages, including the visual Appearance page and its live Look/Layout editors. Based on the real-pong screenshot review and the subsequent wireframes. This note governs implementation; older handoff sketches do not exclude the editors from this work.

Approach

  1. Reuse Android Views/Material Components, existing semantic color roles, typography and shapes. No Compose migration. Add shared 8dp-family dimensions where missing.
  2. Shared settings chrome: remove stacked section dividers, replace fixed wrapping chip walls with compact navigation, fix search padding, and let long segmented choices adapt instead of truncating or shrinking below readable sizes.
  3. Settings information architecture: task-based root groups, focused Keyboard/Apps/Display destinations where useful, and one canonical App behavior page for shared vibration, idle activity and Recents. Keep the existing visual Appearance entry; its Surface style, Layout and Theme & fonts routes are distinct.
  4. Short, state-oriented product copy across Terminal, Status, Notifications, Keyboard, Apps, Display, AI, Permissions, Diagnostics and About. Retain privacy, permission, network, prerequisite and destructive-action consequences.
  5. Polish actual Appearance, Look and Layout panels: semantic tonal grouping, readable labels/values, selected-state feedback, insets and control hierarchy. Preserve live preview, geometry and commit-on-Done behavior.

Worker ownership

  • Shared components: shared Settings base/components/layouts, global styles/attrs, optional slider-value suffix and optional-status presentation APIs. Own their shared unit tests.
  • Navigation and copy: SettingsActivity, Settings XML menus, termux destination fragments, new focused subpage classes/XML, strings.xml plus a separate menu-copy resource, and root/search/destination tests. Do not touch shared components or Appearance/editor resources.
  • Appearance editors: wallpaper picker page/layout/strings, surface editor panel/controller/XML/strings, Layout controller/frame/EditorM3, private editor style/dimension resources, and editor/picker tests. Do not touch SettingsActivity, shared styles.xml or renderer geometry.

Preserve

  • Preference keys/values, per-orientation sizing, allowed deep links, search-index routes and retained Back stacks.
  • Dynamic/light/dark themes and native Views compatibility. Menus remain keyboard/TalkBack reachable and meaningful with large text.
  • Rendering/masks, terminal input, voice/model engines, geometry, existing confirmations and unsaved-editor behavior.
  • Existing specialized font, model and extra-key editors; shared styling applies without deleting capabilities.

Verification

Workers never build/test. The main session merges the disjoint worker commits, runs assembleDebug and unit tests with output saved to logs, and delegates log reading to Explore. Lint where feasible. Visual checks use a local test device/emulator, not an unasked install on pong. Report exact coverage and any failing or unverified checks. Known lazy-mode singleton test flake must be identified by test name, not failure counts.

No release, push, or pong install is authorized by this rework request.
