A terminal is a window into a conversation between a person and a program. Long before graphical desktops, the conversation happened over a physical device with a keyboard and a printer or a small screen, wired to a larger computer somewhere else in the building. The device sent each key press down the wire as a character, and the computer sent characters back to be printed. Everything a modern terminal does still follows that shape: characters go in, characters come out, and both sides agree on what a few special characters mean.

The program on the other end of the wire is usually a shell. A shell reads a line of text, splits it into a command and its arguments, finds the program the command names, and starts it. While that program runs, the shell steps aside and lets it own the conversation. The program can read what the person types and write whatever it likes to the screen. When it exits, the shell takes the conversation back and prints a prompt to show it is listening again.

Between the shell and the window sits a layer that pretends to be the old physical device. It keeps a grid of character cells, moves an invisible cursor around that grid, and interprets short control sequences that programs send to clear a line, change a colour or jump to a position. A full-screen editor draws its whole interface by sending nothing but those sequences and ordinary text. The window never knows what the editor is; it only knows which cell holds which character in which colour.

Input travels the other way through the same layer. Ordinary keys become their characters. Arrow keys, function keys and combinations with the control key become short sequences of their own, so a program can tell a cursor movement apart from a letter. The layer can also hold a line of typed text back until the person presses enter, or hand over every key the instant it arrives, depending on what the running program asks for.

Because the whole exchange is text, it can be recorded, replayed, sent across a network or handed from one program to another without either side noticing. That plainness is why the terminal has outlived every fashion in computing that tried to replace it. A new device only has to speak the same small vocabulary of characters and control sequences, and every program ever written for a terminal will run on it unchanged.
