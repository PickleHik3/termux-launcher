# Terl: a new name and a new repository for v2

The name "termux-launcher" leads many people to take the project for part of Termux, and the
GitHub repository shows "forked from termux/termux-app" under its name; people do not read the
README. The tiling desktop (ADRs 0037 and 0038) is a pivot large enough to start under a name of
its own.

## Decision

1. v2 ships as **Terl: Terminal Launcher**, its first release under that name.
2. It moves to a new, standalone repository (not a GitHub fork) holding the full git history. The
   termux-launcher repository is archived with a pointer to Terl.
3. Package name (`com.termux`), signing key and version code line stay, so Terl installs over
   termux-launcher as an update. All three editions (main, Nix edition, io.vaj.package) carry on.
4. Termux's GPLv3 licence and the credit to Termux stay in the code and the README.

## Considered

- **Rename the repository and ask GitHub to detach it from the fork network.** Keeps 358 stars,
  issues and old links, but the repository's own past still says termux-launcher.
- **A new repository with fresh history.** The cleanest break, but loses blame and history, and
  leaves attribution to the licence files alone.
- **Carry only the main edition.** One build per release, but Nix-edition and io.vaj users would
  get no v2.

## Consequences

- Stars, issues and watchers stay on the archived repository; open issues that still matter are
  moved by hand.
- `gh` commands, CI, release notes, Discord posts, tlstore and the docs name the new repository;
  `TermuxConstants`, the package name and the prefix do not change.
- Keeping `com.termux` keeps the shared user id with Termux plug-ins and the sdk 28 target
  (AGENTS.md) exactly as they are.
